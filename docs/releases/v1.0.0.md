# regiondb v1.0.0

`v1.0.0` is the first stable regiondb release. It establishes the production
`fs_split_v1` readability, text protocol version 1, durability, and server CLI
contracts described in the
[stable compatibility policy](../COMPATIBILITY.md).

## Release channel

This release is a non-prerelease GitHub Release and is eligible to be marked
`latest`. Stable `v1.x` updates follow SemVer for the declared compatibility
surfaces.

## Highlights

- Packed chunk values and explicit block-presence state persist in the
  checksummed `fs_split_v1` layout.
- The authenticated TCP/TLS protocol supports single-block, exact chunk-state,
  and ordered batch operations with bounded framing and runtime resources.
- `relaxed`, `fsync-wal`, and `fsync-checkpoint` expose explicit
  acknowledgement and recovery boundaries.
- Linux, macOS, and Windows archives are produced for AMD64 and ARM64 with
  SHA-256 checksums and per-archive SBOMs.
- Native matrix, race, lint, CodeQL, integration, stress, crash/recovery, and
  frozen format-fixture suites form the stable release gate.

## Compatibility

Stable `v1.x` readers accept `RGDBSPL2` chunks and `RGDBWAL2` records written
by this release. They also read the documented `RGDBSPL1` and `RGDBWAL1`
prerelease fixtures. A later writer may use a newer format, so copying a
complete backup before upgrade remains required for rollback.

Wire protocol version 1 preserves the existing request grammar, response
framing, commands, error codes, and semantics. `MSET` is ordered but is not
atomic across items; `MGET` is not a cross-item snapshot. Durability remains a
server startup choice and is not negotiated on the wire.

The stable CLI executable is `regiondb`. Existing server flags and accepted
values retain their documented meanings. Exact diagnostics, log fields, and
help formatting are not stable APIs.

## Release verification

Before publication:

1. Start from a clean `main` revision and run `scripts/test/quick.sh` and
   `scripts/test/full.sh`.
2. Confirm the Linux, macOS, and Windows test matrix, race detector,
   golangci-lint, CodeQL, repeated stress gate, and durability crash matrix are
   green for that revision.
3. Run the frozen compatibility fixture tests for `RGDBSPL1`, `RGDBSPL2`,
   `RGDBWAL1`, and `RGDBWAL2`.
4. Build the six GoReleaser archives for Linux, macOS, and Windows on AMD64
   and ARM64 from the release tag.
5. Verify every archive against `SHA256SUMS` and confirm that each archive has
   a Syft JSON SBOM.
6. Extract every archive on its target operating system, run
   `regiondb -version`, and perform an authenticated TCP smoke test against a
   temporary data directory.
7. Publish a non-prerelease GitHub Release and mark it `latest`.

## Upgrade and rollback

Stop the writer and make a complete data-directory backup before upgrading.
The first stable release reads the prerelease chunk and WAL generations
without an offline conversion. Rewriting a legacy chunk or replaying a legacy
WAL publishes the current format.

Rollback to an older release is not guaranteed after a newer writer has
modified the directory. Restore the pre-upgrade backup instead. Geometry must
remain unchanged when reopening a directory.

## Explicitly out of scope

- Compatibility guarantees for internal Go packages or an embedding API.
- The experimental `fs_region_v1` backend or migration to or from it.
- Distributed operation, replication, clustering, or sharding.
- Cross-chunk or cross-item transactions.
- Unverified platform, architecture, filesystem, or durability combinations.
- Performance guarantees, artifact signing, installers, package repositories,
  or container publication.
