# regiondb v1.1.0

`v1.1.0` is a stable, backward-compatible feature release on the `v1.x` line.
It adds bounded world reads, persisted chunk versions with conditional
operations, an explicit global durability barrier, compressed checkpoint
images, bounded metrics and maintenance, and a read-only verifier, without
weakening any contract declared by the
[stable compatibility policy](../COMPATIBILITY.md).

## Release channel

This release is a non-prerelease GitHub Release and is eligible to be marked
`latest`.

## Highlights

- Bounded world reads: deterministic paginated `CHUNKSCAN` plus `CHUNKRANGE`
  and `CHUNKRADIUS` with checked coordinates, a 256-chunk limit, and a 64 MiB
  encoded response cap.
- Persisted chunk versions, single-chunk compare-and-swap, and atomic
  conditional multi-chunk commit decisions with crash-recoverable intents.
- `WALFLUSH` as a global recoverability barrier in every steady-state
  durability mode, plus stable snapshot generations for concurrent read-only
  loads.
- Optional ZRLE for checkpoint images and `CHUNKBINC` responses, fixed
  cardinality Prometheus metrics, and the read-only `regiondb-verify` integrity
  scanner.
- Recency-based bounded cache with second chances, bounded maintenance queue,
  inline backpressure, and deterministic drain on shutdown.
- Security remediation: no default token in any artifact or image, auth-enabled
  startup refuses an empty token, validated intent-path grammar and
  containment, bounds-checked slot writes, and exclusive/no-follow temporary
  file creation where supported.

## Compatibility

Existing `RGDBSPL1`, `RGDBSPL2`, `RGDBWAL1`, and `RGDBWAL2` data remains
readable. `RGDBSPL3` checkpoint images and version, generation, and intent
metadata are forward additions; opening newer data with an older binary is not
promised.

Wire protocol version 1 keeps its grammar, response framing, error codes, and
semantics for existing commands. `MSET` still applies its successful prefix
before an error. `CHUNKBATCH` has one atomic commit decision, but separate
reads and commands do not form a multi-chunk snapshot.

The stable CLI executable remains `regiondb`; `regiondb-verify` is a read-only
companion tool. Exact diagnostics, log fields, and help formatting are not
stable APIs.

## Known limitations

- Chunk images and WAL records retain one whole-artifact CRC-32 without an
  independently verifiable header CRC. CRC-32 detects corruption but is not
  cryptographic authentication.
- The verifier reports a retained version whose empty image was removed by
  checkpoint collection as `image_missing`; v1.1 has no metadata that
  distinguishes that intentional state from accidental image loss.
- `fs_region_v1` remains experimental, opt-in, unavailable to the server and
  verifier, and outside durability, migration, and compatibility guarantees.

## Release verification

Before publication:

1. Start from a clean `main` revision and run `scripts/test/full.sh`, which
   covers vet, tests, the security and hardened suites, race, integration,
   crash/recovery, and the repeated stress gate.
2. Confirm the Linux, macOS, and Windows matrix, golangci-lint, CodeQL,
   durability crash matrix, and stress flake gate are green for that revision.
3. Run the frozen compatibility fixture tests for `RGDBSPL1`, `RGDBSPL2`,
   `RGDBSPL3`, `RGDBWAL1`, and `RGDBWAL2`.
4. Build the six GoReleaser archives for Linux, macOS, and Windows on AMD64
   and ARM64 from the release tag.
5. Verify every archive against `SHA256SUMS` and confirm that each archive has
   a Syft JSON SBOM.
6. Extract an archive, run `regiondb -version`, and perform an authenticated
   TCP smoke test against a temporary data directory.
7. Publish a non-prerelease GitHub Release and mark it `latest`.

## Upgrade and rollback

Stop the writer and make a complete data-directory backup before upgrading.
`v1.1.0` opens `v1.0.0` directories without an offline conversion; rewriting a
chunk or replaying a WAL publishes the current format, after which rollback to
an older binary is not guaranteed. Restore the pre-upgrade backup instead.
Geometry must remain unchanged when reopening a directory.

## Explicitly out of scope

- Compatibility guarantees for internal Go packages or an embedding API.
- The experimental `fs_region_v1` backend or migration to or from it.
- Distributed operation, replication, clustering, or sharding.
- Cross-chunk transactions beyond the documented conditional commit decision.
- Unverified platform, architecture, filesystem, or durability combinations.
- Performance guarantees, artifact signing, installers, package repositories,
  or container publication.
