# regiondb v0.1.1-alpha

`v0.1.1-alpha` is a stabilization release for the first engineering alpha.
It is suitable for evaluating the implemented chunk paths and recovery
behavior, not for production data or compatibility-sensitive deployments.

## Validation added since v0.1.0-alpha

- The CI matrix runs vet, tests, and builds on Linux and macOS. Windows covers
  the packages that do not depend on the Unix-only writer lock. Linux also
  runs the complete test suite with the race detector.
- A repeatable stress scenario exercises concurrent reads and writes across a
  working set larger than the bounded cache. It checks read consistency and
  the cache capacity after eviction cycles.
- Protocol benchmarks cover authenticated `PING`, `INFO`, hexadecimal
  `CHUNK`, and binary `CHUNKBIN` response paths without imposing an unstable
  performance threshold.
- Recovery tests cover WAL truncation inside a record header and checksum,
  repeated replay of replacement records, and four 257-record
  checkpoint/reopen cycles.

The release gate requires a successful cross-platform matrix, repeated stress
run, recovery suite, and benchmark bundle before the prerelease is published.
The benchmark artifact contains its inputs, raw JSON output, environment
manifest, and a `SHA256SUMS` file covering both bundle documents.

## Contracts and compatibility

This release does not change the wire protocol, on-disk format, command-line
interface, or Go API from `v0.1.0-alpha`. The exact current contracts are
described in the [protocol](../PROTOCOL.md),
[storage](../STORAGE_FORMAT.md), and
[concurrency](../CONCURRENCY.md) specifications.

## Explicitly out of scope

- Stable compatibility guarantees or production-readiness.
- Migration tooling, replication, multi-process readers, transactions, or
  snapshots.
- A portable writer lock. The server and `fs_split_v1` writer remain limited
  to Unix platforms that provide `flock`.
- Prebuilt cross-platform archives, an SBOM, container images, or automated
  data repair.

Do not rely on an alpha data directory remaining readable by a later release.
Back up or discard evaluation data before upgrading.

## Known limitations

- The server uses one shared authentication token and does not provide
  per-user authorization.
- Plaintext TCP exposes the token and data to the network. Use TLS for
  untrusted networks and manage certificates outside regiondb.
- One process owns a data directory for writing. A second process is rejected,
  and there is no read-only process role.
- An absent chunk is distinguishable through chunk reads, but block reads
  return zero for absent data and `EXISTS` reports whether the current block
  value is nonzero.
- Durability guarantees are limited to the documented filesystem calls.
  Hardware, filesystem, and operating-system behavior may provide weaker
  persistence.
- Recovery validates complete WAL records and discards a final partial record;
  corruption in a complete record fails startup closed and has no automated
  repair path.

## Benchmark caveats

The benchmark programs and focused protocol benchmarks are diagnostic tools,
not performance guarantees. Results depend on geometry, durability mode,
cache state, filesystem, hardware, operating system, server settings, and
whether TLS is used. The automated smoke tests validate completion and output
structure only.

The attached direct-storage bundle is reproducible from its recorded seed,
operation count, workload, durability mode, revision, Go version, OS, and
architecture. Verify it from the extracted artifact directory with:

```sh
sha256sum -c SHA256SUMS
```

## Upgrade and rollback

There is no supported migration path into or out of this alpha. The storage
format is unchanged from `v0.1.0-alpha`, but users should still stop the server
before copying a data directory. To roll back an evaluation, restore a
complete backup created by the same version and geometry, or start with an
empty directory.
